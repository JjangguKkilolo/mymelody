# 검증

## 자동 테스트

```powershell
dotnet test MyMelody.slnx -c Release
```

Core 테스트는 가상 시계로 성장 경계, 중복 없는 뽑기, 수동·자동 전환, 30초 유예, 자정 분할, 잠금/절전과 동등한 suspend, 시계 변경, 저장 실패 재시도, 5초 자동 저장, 일일 백업, 손상·지원하지 않는 백업, 시작 시 DB 복구를 검증합니다.

Update 테스트는 읽기 전용 확인, 사용자가 요청한 다운로드, 중복 작업 방지, 정식 신규 버전 판정, 취소·검증 오류·재시도, MIDI 메시지 필터를 검증합니다.

2026년 9월 14일 기준 Core 22개, Update·MIDI 25개, 총 47개를 통과했습니다.

1.0.1에서는 세션 표시의 30분 경계, 기존 원본 불변, 날짜·수동/자동 경계, 재시작·백업복원 후 보존을 확인하는 테스트 12개를 추가했습니다. Core 34개와 Update·MIDI 25개, 총 59개를 통과했으며, 화면 검사에서도 23초와 30초 기록이 인정 시간 53초인 한 세션으로 표시되는지 확인합니다. 데이터베이스 구조와 저장된 연습 구간은 변경하지 않습니다.

1.1.0에서는 기존 9종 ID를 고정한 구버전 SQLite·ZIP 백업을 구성하는 회귀 테스트 2개를 추가했습니다. 기존 세션 ID·시각·인정 시간·음표 수·설정·표시 대상·육성 대상을 유지한 채 새 양·계란만 뽑고, 11종 백업과 구버전 백업을 왕복 복원합니다. 마지막 기존 친구가 미완료라면 먼저 완성해야 하며, 성장 완료 이후의 기록이 경험치에 중복 반영되지 않는지도 확인합니다.

1.1.0의 테스트 결과는 Core 36개, Update·MIDI 25개로 **총 61개 통과**입니다.

1.2.0에서는 과거 9종·11종 카탈로그의 완료/미완료 데이터를 각각 검증합니다. 기존 11종을 완료한 데이터에서는 공룡만 새로 뽑을 수 있고, 미완료 친구가 있으면 먼저 완성해야 합니다. 재시작·구버전 백업·12종 백업 복원 후 기존 기록과 수집 상태를 보존합니다.

1.2.0 테스트는 Core 38개와 Update·MIDI 25개, **총 63개 통과**입니다.

1.3.0에서는 표시할 성장 단계를 별도로 저장합니다. 추가한 Core 테스트 11개는 도달한 단계만 선택, 실제 성장·연습 기록 불변, 고정/자동 표시, 새 뽑기 초기화, 재시작·백업 복원, 잘못된 단계 데이터 거부, 저장 실패 시 선택 원복을 검증합니다. 이전 9종·11종 데이터에 새 필드가 없어도 현재 성장 단계를 자동 표시하는지 확인합니다. SQLite 스키마 1과 기존 기록을 유지하고, 선택 항목만 저장 JSON에 추가합니다.

2026년 9월 15일 1.3.0 패키징 검사에서 Core 49개와 Update·MIDI 25개, **총 74개 통과**를 확인했습니다.

## 실제 업데이트

`tests/MyMelody.UpdateSmoke`는 개인 저장과 다른 패키지 ID로 두 시험 버전을 만들고 실제 Velopack 프로세스로 업데이트·재시작합니다. 13시간 연습, 캐릭터·설정, 업데이트 전 백업이 유지되는지 검증합니다. 설치형과 포터블을 모두 검사합니다.

1.0.1 변경 검증에서는 기존 1.0.0 시험 패키지를 다시 빌드하지 않고 보존한 채, 새 Core를 포함한 1.0.1로 업데이트했습니다. 설치형과 포터블 모두에서 원시 세션 ID·시각·인정 시간·음표 수·기록 방식과 캐릭터·설정의 정확한 일치, 업데이트 전 백업 복원을 확인했습니다.

## 화면 렌더링

```powershell
dotnet run --project src/MyMelody.App -c Release -- --ui-smoke artifacts/ui-qa
```

이 모드는 지정한 출력 폴더 아래 새 시험 데이터 폴더를 만들고 개인 기록·실제 MIDI·자동 실행 설정을 사용하지 않습니다. 실제 WPF 화면을 100·150·200%로 렌더링하며 12종의 36개 성장 모습·72개 표정 프레임을 확인합니다. 시험 기록은 실제 연습으로 제시하지 않습니다.

GitHub Actions와 패키징 스크립트도 이 검사를 실행합니다. 카탈로그와 일치하는 12개 PNG 시트, 각 시트의 2열×3행 정사각형 셀과 전체 테두리의 투명 여백, 성장·표정 프레임 차이, 최소 창 크기, 모든 페이지, 백업 왕복 검사를 통과해야 배포할 수 있습니다. 생성 이미지의 알파 반올림 잔여 값 1/255까지 허용하며, 그보다 진한 픽셀이 셀 경계에 닿으면 잘림으로 거부합니다. 열린 눈과 감은 눈을 각각 모은 실제 크기 미리보기도 생성합니다.

1.0.2부터는 앱 ICO의 9개 크기(16–256픽셀), 창·트레이 로딩, 실행 파일의 아이콘 리소스도 확인합니다. 같은 아이콘을 밝은 배경과 어두운 배경에 실제 크기로 렌더링한 `icons-preview.png`를 검사 결과 폴더에 저장합니다.

1.1.1에서는 실제 `SpriteView`를 총 330번 렌더링해 크기 통일을 검증합니다. 66개 표정 모두 기본 96 DIP·100%에서 보이는 높이가 69픽셀이고 바닥선은 y=84입니다. 150%에서는 103–104픽셀, 200%에서는 138–139픽셀이며, 최소 48 DIP와 최대 384 DIP에서도 높이 차이는 1픽셀 이내였습니다. 모든 구성에서 눈 깜빡임 전후 가로 중심·바닥선 이동은 0픽셀입니다. `size-checks.json`에 개별 측정값을 저장하며, 높이 차이 2픽셀·바닥선 또는 깜빡임 중심 차이 1픽셀을 넘거나 외형이 잘리면 배포 검사가 실패합니다. PNG 원본·캐릭터 ID·개인 데이터 저장 구조는 변경하지 않았습니다.

1.2.0부터는 새 종류까지 포함한 모든 표정이 기본 96 DIP·100%에서 기존 배포 기준인 높이 69픽셀·바닥선 y=84를 유지해야 합니다. 12종에서 총 360회 렌더링을 검사합니다. 캐릭터끼리 같은지뿐 아니라 이전 배포 크기와 같은지도 확인하므로, 추가된 소품 때문에 모두 작아지는 변경을 거부합니다.

실제 1.2.0 배포용 앱에서 72개 표정 모두 기본 높이 69픽셀·바닥선 y=84를 확인했습니다. 기존 11종의 66개 개별 렌더링 PNG를 1.1.1 배포용 앱 결과와 SHA-256으로 비교해 전부 일치했습니다. 원본 이미지뿐 아니라 표시 결과도 그대로 유지됩니다.

1.3.0 화면 검사는 실제 컬렉션 버튼으로 이전 단계를 미리 보고 적용합니다. 미리보기만으로 SQLite·경험치·세션·팝업이 바뀌지 않는지, 미래/미소유 단계가 잠기는지, 완료한 친구의 세 단계를 별도로 표시하는지, 홈에는 실제 성장 단계가 남는지 검사합니다. 고정한 모습의 연습 후 유지·백업 복원·자동 표시 복귀, 카드 재구성 후 미리보기와 스크롤 유지도 확인합니다. 기존 72개 표정·360회 크기 검사도 계속 실행합니다.

1.3.0 배포용 앱에서 단계 선택 검사와 100·150·200% 화면 검사, 760 DIP 너비의 2열 배치·단계 버튼 잘림 검사를 통과했습니다. 72개 표정의 기본 크기 렌더링 PNG를 1.2.0 배포용 앱과 SHA-256으로 비교해 모두 일치했습니다. 그림 원본과 표시 크기는 그대로입니다.

## 실제 장비와 환경

사용자에게 MIDI 건반이 없어 실제 건반·Cakewalk 동시 연주 검증은 친구가 진행하기로 했습니다. [테스트 안내](friend-testing.md)를 사용하세요. 물리 디스플레이 DPI 변경과 깨끗한 SDK 미설치 Windows VM도 별도 확인 항목입니다. 자동 테스트 또는 번들 런타임 확인을 이 장비 검증의 대체로 표시하지 않습니다.
